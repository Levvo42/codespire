# Team Retrospective and Lessons Learned

## Meetings

The morning meetings have been working well, so we should continue using them.

However, we need to make sure that everyone understands what is being discussed. If someone loses track during a meeting, they should speak up immediately. We should also feel comfortable asking questions whenever something is unclear.

## Git and Branching

Working with Git branches has been somewhat challenging, but we should continue avoiding direct work on the `main` branch. This is a good development practice and will become increasingly important when working on larger projects and in professional environments.

Although we have had some difficulties with branching, pushing, and merging, this is actually useful experience. We will likely encounter similar situations many more times, both in future projects and in the workplace. Solving these problems now will make us more comfortable working with Git in larger teams.

Next Monday, we will have a proper walkthrough of GitHub. This should help everyone become more comfortable using features such as **Issues** and make us more self-sufficient when managing our own tasks.

## Division of Work

The division of work has generally been good. However, it can sometimes be difficult to get started on a task because we are unsure whether our implementation will fit with the rest of the project.

Even though we use linters and coding conventions, everyone naturally has their own way of writing code. We need to find a common approach that works well for everyone and makes it easier to contribute without worrying too much about whether the code looks "correct."

Clearer conventions and communication should help with this.

## Communication

Our communication is good overall, but there is always room for improvement. Compared with many other group projects, the communication has worked particularly well.

One area we need to improve is making tasks and requirements clearer. There have been situations where we have misunderstood each other or had different interpretations of what needed to be done.

To improve this, we should:

- Make tasks and requirements more specific.
- Ask questions as soon as something is unclear.
- Speak up during meetings if we lose track of the discussion.
- Make sure everyone has the same understanding before starting a task.
- Communicate when something is blocking our progress.

## Project Momentum

The project had a somewhat slow start, and it took longer than expected before we started getting significant work done. This may partly be because this is the first project we are working on together and we are still learning how to work as a team.

Going forward, we should try to maintain more momentum by making tasks clearer, becoming more comfortable with GitHub, and taking more ownership of individual tasks.

## Going Forward

Overall, we should continue working roughly the way we have been working, while making some improvements to our workflow.

Our main focus going forward will be:

1. Continue with the morning meetings.
2. Avoid working directly on `main`.
3. Improve our understanding of Git branching, pushing, and merging.
4. Make tasks and requirements clearer.
5. Ask questions and communicate immediately when something is unclear.
6. Establish coding conventions that everyone is comfortable following.
7. Use GitHub Issues to organize and track our work.
8. Take more individual ownership of tasks to keep the project moving.
9. Make sure everyone reads the tutorials available under `docs/team/tutorials`.

The goal is to become more comfortable working together as a team while also developing good habits that will be useful in future group projects and professional software development.
