# Project structure

Overview of the repo, what the config files do, and where to put things.

## Folders

```
index.html          Start page — Vite's main entry point
pages/              All other HTML pages (lobby, singleplayer, tutorial, credits)
src/
  js/               JavaScript (one entry script per page in js/pages/)
  scss/             SCSS styles (imported from JS, Vite compiles them)
  assets/           Images/audio/fonts that the code imports (see below)
public/             Files copied to the build as-is (see below)
server/             The Worker: our /api server (see tutorials/backend.md)
migrations/         Database structure changes, numbered SQL files
scripts/            Node scripts, e.g. seed-questions.js (questions -> seed.sql)
docs/               Team docs, tutorials, API logs and meeting notes
dist/               Build output — generated by `npm run build`, never edited,
                    never committed (gitignored)
node_modules/       Installed dependencies — never committed (gitignored)
.wrangler/          Your local database and Wrangler temp files (gitignored)
.github/workflows/  GitHub Actions: CI checks on every pull request, and the
                    Database workflow that updates the online databases
.vscode/            Shared VS Code settings and recommended extensions
```

The formatting and linting config files in the root (`.prettierrc.json`,
`eslint.config.js`, `stylelint.config.js`, `.htmlvalidate.json`,
`.gitattributes`) are explained in
[tutorials/code-quality.md](tutorials/code-quality.md).

## package.json — what every field does

JSON does not allow comments, so the file is explained here instead:

| Field                                              | What it does                                                                                                                                                                                                                                                                                                      |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`, `version`, `description`                   | Identifies the project. Only informational for us.                                                                                                                                                                                                                                                                |
| `private: true`                                    | Safety lock: makes `npm publish` refuse to upload the project to the public npm registry by accident.                                                                                                                                                                                                             |
| `scripts.dev`                                      | `npm run dev` — starts the Vite dev server with hot reload. Use this while working.                                                                                                                                                                                                                               |
| `scripts.build`                                    | `npm run build` — creates the optimized production build in `dist/`.                                                                                                                                                                                                                                              |
| `scripts.preview`                                  | `npm run preview` — serves the finished `dist/` build locally so you can check it before deploying. Run `build` first.                                                                                                                                                                                            |
| `repository`, `bugs`, `homepage`                   | Links to our GitHub repo. Informational.                                                                                                                                                                                                                                                                          |
| `license`                                          | ISC (npm's default). Informational for a school project.                                                                                                                                                                                                                                                          |
| `type: "module"`                                   | Makes Node treat `.js` files as ES modules (`import`/`export`). Required for our Vite setup.                                                                                                                                                                                                                      |
| `scripts.format`, `scripts.lint*`, `scripts.check` | Formatting and linting commands. `npm run check` runs all of them — see [tutorials/code-quality.md](tutorials/code-quality.md).                                                                                                                                                                                   |
| `devDependencies`                                  | Tools needed to develop/build, not shipped to users: `vite` (dev server + bundler), `sass` (compiles SCSS), `wrangler` (runs the Worker and database locally), and the code-quality tools `prettier`, `eslint` (+ `@eslint/js`, `globals`), `stylelint` (+ `stylelint-config-standard-scss`) and `html-validate`. |
| `allowScripts`                                     | npm's consent list for packages that run install scripts. `@parcel/watcher` (used by sass for file watching) is allowed. Added automatically by npm — leave it.                                                                                                                                                   |

`package-lock.json` records the exact version of every installed package so
all four of us get identical installs. It **is** committed — don't delete it,
and commit it when it changes.

## vite.config.js

Commented inline — read the file. Short version: every HTML page must be
listed under `build.rollupOptions.input`, or it will be missing from the
production build. **When you add a new page in `pages/`, add it there too.**

Only the HTML pages are listed there, not the scripts: each page loads its own
entry script from `src/js/pages/` with a `<script type="module">` tag, and
Vite follows that tag on its own. So a new page is two steps — add the page
here, and create its script. See
[tutorials/javascript.md](tutorials/javascript.md#entry-scripts-one-per-page).

The `server.proxy` setting sends every `/api/...` request from the dev server
(localhost:5173) on to the Worker (`npx wrangler dev`, localhost:8787), so the
game can call its API while you develop.

## wrangler.jsonc

The Cloudflare config, read by Wrangler (locally and when deploying). `.jsonc`
is JSON that allows comments and trailing commas.

| Field                   | What it does                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------ |
| `name`                  | The Worker's name on Cloudflare.                                                           |
| `compatibility_date`    | Which version of the Workers runtime to behave like.                                       |
| `main`                  | The server code: `server/index.js`.                                                        |
| `assets.directory`      | Everything that isn't `/api` is served from `dist/` (the built game).                      |
| `d1_databases`          | The live database. `binding` is the name the code uses: `env.codespire_db`.                |
| `preview_database_id`   | The preview database, so `--preview` in d1 commands targets it.                            |
| `previews.d1_databases` | The database that pull request previews use instead of the live one (same `binding` name). |

How the server and database work is explained in
[tutorials/backend.md](tutorials/backend.md).

## Secrets

The game has no secrets in the code: the browser bundle is public, so anything
in it can be read by anyone. Secrets (like the Cloudflare API token GitHub uses)
are stored as GitHub secrets and never committed.

## Where do assets go?

Two locations, two purposes:

**`src/assets/`** — anything you `import` or reference from HTML/CSS/JS:
images, audio, fonts. Vite processes these (optimizes, adds cache-busting
hashes) and only includes files that are actually used.

```js
import logo from "../assets/images/logo.png";
imgElement.src = logo;
```

**`public/`** — files that must keep their exact name and path: favicon,
`robots.txt`, `sitemap.xml`, or files whose URL is built at runtime as a string. Vite copies
them to `dist/` untouched. Reference them with a root-absolute path:

```html
<img src="/fallback/missing-avatar.png" alt="" />
```

Rule of thumb: **default to `src/assets/`**; use `public/` only when you have
a reason. Do **not** create an `assets/` folder at the repo root — files there
would work in the dev server but 404 in the production build.

One git gotcha: git does not track empty folders. Create `src/assets/`
subfolders (e.g. `src/assets/images/`) when you add the first real file to
them, not before.
