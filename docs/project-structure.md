# Project structure

Overview of the repo, what the config files do, and where to put things.

## Folders

```
index.html          Start page — Vite's main entry point
pages/              All other HTML pages (lobby, singleplayer, tutorial, credits)
src/
  js/               JavaScript (main.js is the entry script)
  scss/             SCSS styles (imported from JS, Vite compiles them)
  assets/           Images/audio/fonts that the code imports (see below)
public/             Files copied to the build as-is (see below)
docs/               Team docs, tutorials and meeting notes
dist/               Build output — generated by `npm run build`, never edited,
                    never committed (gitignored)
node_modules/       Installed dependencies — never committed (gitignored)
```

## package.json — what every field does

JSON does not allow comments, so the file is explained here instead:

| Field                            | What it does                                                                                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`, `version`, `description` | Identifies the project. Only informational for us.                                                                                                              |
| `private: true`                  | Safety lock: makes `npm publish` refuse to upload the project to the public npm registry by accident.                                                           |
| `scripts.dev`                    | `npm run dev` — starts the Vite dev server with hot reload. Use this while working.                                                                             |
| `scripts.build`                  | `npm run build` — creates the optimized production build in `dist/`.                                                                                            |
| `scripts.preview`                | `npm run preview` — serves the finished `dist/` build locally so you can check it before deploying. Run `build` first.                                          |
| `repository`, `bugs`, `homepage` | Links to our GitHub repo. Informational.                                                                                                                        |
| `license`                        | ISC (npm's default). Informational for a school project.                                                                                                        |
| `type: "module"`                 | Makes Node treat `.js` files as ES modules (`import`/`export`). Required for our Vite setup.                                                                    |
| `devDependencies`                | Tools needed to develop/build, not shipped to users: `vite` (dev server + bundler) and `sass` (compiles SCSS).                                                  |
| `allowScripts`                   | npm's consent list for packages that run install scripts. `@parcel/watcher` (used by sass for file watching) is allowed. Added automatically by npm — leave it. |

`package-lock.json` records the exact version of every installed package so
all four of us get identical installs. It **is** committed — don't delete it,
and commit it when it changes.

## vite.config.js

Commented inline — read the file. Short version: every HTML page must be
listed under `build.rollupOptions.input`, or it will be missing from the
production build. **When you add a new page in `pages/`, add it there too.**

## .env / .env.example

`.env` holds local secrets (the quiz API key) and is gitignored — everyone
creates their own by copying `.env.example`. Two rules:

- Variables must be prefixed `VITE_` (e.g. `VITE_QUIZ_API=abc123`), otherwise
  Vite does not expose them to browser code.
- Read them in JS with `import.meta.env.VITE_QUIZ_API`.

Note: `VITE_` variables end up visible in the shipped bundle, so never put a
real secret there — fine for a public quiz API key.

## Where do assets go?

Two locations, two purposes:

**`src/assets/`** — anything you `import` or reference from HTML/CSS/JS:
images, audio, fonts. Vite processes these (optimizes, adds cache-busting
hashes) and only includes files that are actually used.

```js
import logo from "../assets/images/logo.png";
imgElement.src = logo;
```

**`public/`** — files that must keep their exact name and path: favicon,
`robots.txt`, or files whose URL is built at runtime as a string. Vite copies
them to `dist/` untouched. Reference them with a root-absolute path:

```html
<img src="/fallback/missing-avatar.png" alt="" />
```

Rule of thumb: **default to `src/assets/`**; use `public/` only when you have
a reason. Do **not** create an `assets/` folder at the repo root — files there
would work in the dev server but 404 in the production build.

One git gotcha: git does not track empty folders. Create `src/assets/`
subfolders (e.g. `src/assets/images/`) when you add the first real file to
them, not before.
